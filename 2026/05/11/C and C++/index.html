1. 命名空间

1.1 为什么要使用命名空间 why？

对于一个大型的工程而言，往往是由若干个人独立完成的，那么就会出现一个问题，在不同的头文件中用了相同的名字来命名所定义的的类或者函数，那么最后就会产生冲突。
名字冲突即在同一个作用域中有多个同名的实体，在C语言中为了避免名字冲突我们只能进行起名约定。

C++为了解决命名冲突，命名空间就应运而生了。
命名空间: 一个可以由用户自己定义的作用域，在不同的作用域中可以定义相同的名字，互不干扰。

1.2 什么是命名空间

命名空间又叫名字空间，是程序员自己命名的内存区域，程序员根据需要，指定一些有名字的作用域，把一些全局实体分别存放到各个命名空间中，从而和其他的全局实体分隔开。

    这些统称为实体。
    那么我们该如何使用命名空间呢？

1.4 命名空间的嵌套使用

类似于文件夹下还可以建立文件夹，命名空间中同样可以定义命名空间，那么问题来了，内层命名空间中的实体该如何访问呢

1.5 匿名命名空间

是的，命名空间同样可以不定义名字，那么不定义名字的命名空间就叫做匿名命名空间（简称匿名空间）。
Q：什么时候我们需要匿名空间呢？
A：如果我们只希望这一部分实体在本文件中起作用，那么我们就可以把它定义在匿名空间中。
like

注意:
如果匿名空间中定义了和全局位置中同名的实体，直接访问会有冲突。
同样，如果使用 :: 作用域限定符，也无法访问到匿名空间中重名的实体，只能访问到全局的实体。

匿名空间使用的注意事项：

  1. 匿名空间不要定义和全局空间中同名的实体。
  2. 匿名空间中的实体不能跨模块调用。

1.6 跨模块调用的问题

一个.c/.cc/*.cpp的文件可以称为一个模块。

(1) 全局变量和函数是可以跨模块调用的

那么对A.cc和B.cc联合编译，就可以实现跨模块调用

(2) 有名命名空间中的实体同样可以跨模块调用

命名空间中的实体跨模块调用时，要在新的源文件中再次定义同名的命名空间，在其中通过extern引入实体。
访问命名空间中的实体时，之前所学的三种方式都可以，但要注意避免冲突。

进行联合编译时，这两次定义被认为是同一个命名空间。

使用规则：如果需要跨模块调用命名空间中的实体，要尽量避免它们与全局位置的实体重名，在使用时尽量采取作用域限定的方式

(3) 静态变量和函数只能在本模块内部使用。

(4) 匿名空间中的实体只能在本模块内使用。
匿名空间中的实体只能在本文件的作用域内有效，它的作用域是从匿名空间声明开始到本文件结束。

extern vs. include:

  • extern外部引入的方式适合管理较小的代码组织，用什么就引入什么，但是如果跨模块调用的关系不清晰，容易出错；
  • include头文件的方式在代码组织上更清晰，但是会一次引入全部内容，相较而言效率比较低。

1.7 使用命名空间的规则

从以往的学习中我们得知，函数可以声明多次，但是只能定义一次；
而命名空间可以多次定义，却不能进行单纯的“声明”。

在同一个源文件中可以多次定义同名的命名空间，被认为是同一个命名空间，所以不能在当中定义相同的实体。

在命名空间中可以声明实体、定义实体，但是不能使用实体。命名空间中的实体一定在命名空间之外使用，可以理解为命名空间只是用来存放实体。

1.8 总结

命名空间的作用：

  1. 避免命名冲突：命名空间提供了一种将全局作用域划分成更小的作用域的机制，用于避免不同的代码中可能发生的命名冲突问题；
  2. 组织代码：将相关的实体放到同一个命名空间；
  3. 版本控制：不同版本的代码放到不同的命名空间中；
    总之，需要用到代码分隔的情况就可以考虑使用命名空间。
    还有一个隐藏的好处：声明主权。

命名空间使用建议：

  1. 提倡在命名空间中定义变量，而不是直接定义全局变量或者静态全局变量。
  2. 对于using 声明语句，建议将其作用域设置为局部而不是全局（*）。
  3. 不要在头文件中使用using编译指令，很可能造成命名空间的污染，在包含该头文件的源文件中访问命名空间定义的实体时，容易出现二义性。
  4. 包含头文件的顺序可能会影响程序的行为，如果一定要使用using编译指令，建议放在所有#include预编译指令后。
    规范补充：include多个头文件，首先放自定义的头文件，再放C的头文件，再放C++的头文件，最后放第三方库的头文件。

2. const关键字

2.1修饰内置类型*

const修饰的变量称为常量，之后不能修改其值。(本质上还是变量，使用时也当作变量来使用，只是被赋予了只读的属性)
整型，浮点型数据都可以修饰，它们被称为const常量。const常量在定义时必须被初始化。

同样我们可以宏定义创建常量。

那么就引申出一个问题：
const常量和宏定义常量的区别

  1. 发生的时机不同：C语言中的宏定义发生时机在预处理时，做字符串的替换；const常量是在编译时（const常量本质还是一个变量，只是用const关键字限定之后，赋予只读属性，使用时依然是以变量的形式去使用）
  2. 类型和安全检查不同：宏定义没有类型，不做任何类型检查；const常量有具体的类型，在编译期会执行类型检查。在使用中，应尽量以const替换宏定义常量，可以减小犯错误的概率。

2.2 修饰指针类型*

以int指针为例，用const修饰有三种形式：
const int *p
int const *p
